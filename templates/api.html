🔌 REST API

Every tool, scriptable. Send a multipart form to /api/v1/… and the finished file comes straight back in the response body — no polling, no download step, nothing left on the server. Errors are always JSON {"error": "…"} with status 400 (something to fix in your request) or 500 (something went wrong here).

POST/api/v1/merge

Merge several files into one PDF. Non-PDF uploads (images, Markdown, DOCX, …) are converted first — see merge_extensions from /api/v1/formats. Returns application/pdf.

FieldRequiredMeaning
files[]yes The uploads, repeated once per file; merged in the order sent.
page_numbersno true/false — stamp sequential page numbers (default true).
number_positionno bottom-right (default), bottom-center or bottom-left.
start_numberno Whole number ≥ 1 the numbering starts at (default 1).
blank_pagesno true/false — pad odd-page sources with a blank page for duplex printing (default false).
bookmarksno true/false — one outline entry per source file (default true).
modeno standard (default) concatenates; interleave zips exactly two files (fronts + backs) into A1, B1, A2, B2…
reverse_secondno Interleave only: flip the second file first, for reversed back-side scans (default true).
curl -X POST http://localhost:5010/api/v1/merge \
  -H "Authorization: Bearer $DOCIST_PASSWORD" \
  -F "files[]=@chapter1.pdf" \
  -F "files[]=@chapter2.pdf" \
  -F "page_numbers=true" \
  -F "number_position=bottom-center" \
  -F "bookmarks=true" \
  -o merged.pdf

POST/api/v1/convert

Convert one file to another format. Ask /api/v1/formats which targets a source supports.

Note: a conversion may legitimately return a different extension than requested — a multi-page .pdf → .png comes back as a .zip of images, because one PDF can't become one PNG. Trust the filename in the Content-Disposition header rather than the target you asked for.

FieldRequiredMeaning
fileyesThe file to convert.
targetyes Target extension, e.g. .png (a bare png works too).
curl -X POST http://localhost:5010/api/v1/convert \
  -H "Authorization: Bearer $DOCIST_PASSWORD" \
  -F "file=@diagram.png" \
  -F "target=.jpg" \
  -OJ    # -OJ keeps the server's filename (it may be a .zip)

POST/api/v1/pages/extract

Keep only the pages you name, in a new PDF. Page numbers are 1-based and inclusive.

FieldRequiredMeaning
fileyesA .pdf upload.
rangesyes Comma-separated pages and ranges, e.g. 1-3,5,8-10. Out-of-range or malformed specs return a 400.
curl -X POST http://localhost:5010/api/v1/pages/extract \
  -H "Authorization: Bearer $DOCIST_PASSWORD" \
  -F "file=@report.pdf" \
  -F "ranges=1-3,5" \
  -o extract.pdf

POST/api/v1/pages/split

Split a PDF into several files, returned as one application/zip bundle.

FieldRequiredMeaning
fileyesA .pdf upload.
modeyes every_n or ranges.
valueyes With every_n: pages per part, e.g. 2. With ranges: ;-separated specs, e.g. 1-2;3-5 — one file per spec.
curl -X POST http://localhost:5010/api/v1/pages/split \
  -H "Authorization: Bearer $DOCIST_PASSWORD" \
  -F "file=@report.pdf" \
  -F "mode=every_n" \
  -F "value=2" \
  -o split.zip

POST/api/v1/watermark

Stamp text across every page. Returns application/pdf.

FieldRequiredMeaning
fileyesA .pdf upload.
textyesThe watermark text.
positionno center (default, diagonal), header or footer.
opacityno Fill alpha between 0 and 1 (default 0.15).
font_sizenoPoints (default 48).
rotationno Degrees, center position only (default 45).
curl -X POST http://localhost:5010/api/v1/watermark \
  -H "Authorization: Bearer $DOCIST_PASSWORD" \
  -F "file=@contract.pdf" \
  -F "text=CONFIDENTIAL" \
  -F "position=center" \
  -F "opacity=0.2" \
  -o watermarked.pdf

GET/api/v1/formats

Discovery, as JSON — no upload needed:

KeyContents
merge_extensions Everything /api/v1/merge accepts (.pdf plus every convertible format).
convert_sources Source extensions /api/v1/convert understands.
convert_matrix {source: [target, …]} — the full conversion map.
curl http://localhost:5010/api/v1/formats \
  -H "Authorization: Bearer $DOCIST_PASSWORD"

Authentication

If this instance runs with DOCIST_PASSWORD set, send that same password as a bearer token on every API call:

-H "Authorization: Bearer $DOCIST_PASSWORD"

The token is compared in constant time and creates no session — each request stands alone. A browser session cookie works too, so fetch() calls from these pages need no header. When the instance has no password configured the API is open and the header can be omitted entirely. Missing or wrong credentials give 401 with a JSON error body.

Limits & behaviour

  • Rate limit: POSTs are capped per client IP — DOCIST_RATE_LIMIT requests (default 30) per DOCIST_RATE_WINDOW seconds (default 60). Over the cap you get 429 with a JSON error and a Retry-After header telling you how many seconds to wait. GETs are never limited.
  • Upload size: a request larger than DOCIST_MAX_UPLOAD_MB (default 50 MB, total request body) is rejected with 413.
  • Nothing is stored: API uploads and results live in a temporary directory for the length of the request only — unlike the web UI, no file is left in the server's output folder.
  • Content checks: uploads are sniffed against their extension, so a renamed file (a ZIP called .pdf) is refused with a 400.
  • Health: GET /healthz needs no auth and returns {"status": "ok"}.
