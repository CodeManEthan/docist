REST API

Every one-file tool, scriptable. The Packet Builder is browser-only. Send a multipart form to {{ api_origin }}/api/v1/… and the finished file comes straight back in the response body: no polling, no download step, nothing left on the server. {% if api_anonymous -%} On this server you can call it with an API key from your account page, counted against your account's daily limit, or with no key at all, counted against your IP at the guest limit of {% if guest_limit %}{{ guest_limit }} operations a day{% else %}no daily cap{% endif %}. For a keyless call, leave out the Authorization line in the examples below. {%- else -%} On this server every POST needs an API key: sign in, verify your email, and create one on your account page. {%- endif %} Errors are JSON; every status is listed under Errors.

POST/api/v1/merge

Merge several files into one PDF. Non-PDF uploads (images, Markdown, DOCX, …) are converted first — see merge_extensions from /api/v1/formats. Returns application/pdf.

FieldRequiredMeaning
files[]yes The uploads, repeated once per file; merged in the order sent.
page_numbersno true/false — stamp sequential page numbers (default true).
number_positionno bottom-right (default), bottom-center or bottom-left.
start_numberno Whole number ≥ 1 the numbering starts at (default 1).
blank_pagesno true/false — pad odd-page sources with a blank page for duplex printing (default false).
bookmarksno true/false — one outline entry per source file (default true).
modeno standard (default) concatenates; interleave zips exactly two files (fronts + backs) into A1, B1, A2, B2…
reverse_secondno Interleave only: flip the second file first, for reversed back-side scans (default true).
paperno letter (default) or a4: the page size for converted files. PDFs keep their own pages, and a duplex blank matches the page before it.
curl -X POST {{ api_origin }}/api/v1/merge \
  -H "Authorization: Bearer $DOCIST_API_KEY" \
  -F "files[]=@chapter1.pdf" \
  -F "files[]=@chapter2.pdf" \
  -F "page_numbers=true" \
  -F "number_position=bottom-center" \
  -F "bookmarks=true" \
  -o merged.pdf

POST/api/v1/convert

Convert one file to another format. Ask /api/v1/formats which targets a source supports.

Note: a conversion may legitimately return a different extension than requested — a multi-page .pdf → .png comes back as a .zip of images, because one PDF can't become one PNG. Trust the filename in the Content-Disposition header rather than the target you asked for.

FieldRequiredMeaning
fileyesThe file to convert.
targetyes Target extension, e.g. .png (a bare png works too).
paperno letter (default) or a4, when the target is .pdf or the conversion goes through one. Read only then.
languageno Image to .txt only: the OCR language code from ocr_languages (default eng), or two joined with +, e.g. eng+spa.

If the server has to tell you something about how it made the file, the response carries an X-Docist-Notes header (plain ASCII text), for example when a Word file was converted with the basic converter.

curl -X POST {{ api_origin }}/api/v1/convert \
  -H "Authorization: Bearer $DOCIST_API_KEY" \
  -F "file=@diagram.png" \
  -F "target=.jpg" \
  -OJ    # -OJ keeps the server's filename (it may be a .zip)

FieldRequiredMeaning

POST/api/v1/pages/ocr

Add an invisible text layer to scanned pages, so the PDF can be searched and copied from. Pages that already have text pass through unless force is on. Returns application/pdf, named <name>_searchable.pdf. A server without Tesseract and Ghostscript answers 400.

FieldRequiredMeaning
fileyesA .pdf upload.
languageno A code from ocr_languages (default eng), or two joined with +, e.g. eng+spa.
deskewno Flag: straighten crooked scans first (default off).
forceno Flag: OCR every page, including ones that already have text (default off).

A flag is on for 1, true, on or yes, and off for anything else.

curl -X POST {{ api_origin }}/api/v1/pages/ocr \
  -H "Authorization: Bearer $DOCIST_API_KEY" \
  -F "file=@scan.pdf" \
  -F "language=eng" \
  -F "deskew=true" \
  -o searchable.pdf

POST/api/v1/export

Get a PDF's pages as images, or its text. With operation=images it returns application/zip, named <name>_images.zip, holding page_001.png, page_002.png, … With operation=text it returns text/plain; charset=utf-8, named <name>.txt: each page starts with a --- Page N --- line, and a form feed separates the pages. A scanned page has no text unless ocr_fallback is on.

FieldRequiredMeaning
fileyesA .pdf upload.
operationyes images or text.
fmtno Images only: png (default) or jpg.
dpino Images only: 30 to 600 (default 150).
ocr_fallbackno Text only. Flag: OCR the pages that have no text layer (default off). A server without Tesseract answers 400.
languageno Text with ocr_fallback only: a code from ocr_languages (default eng), or two joined with +.
curl -X POST {{ api_origin }}/api/v1/export \
  -H "Authorization: Bearer $DOCIST_API_KEY" \
  -F "file=@report.pdf" \
  -F "operation=images" \
  -F "dpi=100" \
  -o pages.zip

curl -X POST {{ api_origin }}/api/v1/export \
  -H "Authorization: Bearer $DOCIST_API_KEY" \
  -F "file=@report.pdf" \
  -F "operation=text" \
  -o report.txt

Authentication

To get an API key, sign in, verify your email, and create one on your account page. The key is shown once, so copy it then. Send it as a bearer token:

-H "Authorization: Bearer $DOCIST_API_KEY"

Keys are stored hashed and create no session; each request stands alone. The browser session cookie is ignored here, so a signed-in browser tab cannot be used to call the API. GET /api/v1/formats and this page need no key. Revoke a key from the account page; resetting your password revokes every key.

{% if api_anonymous %}

This server also takes keyless calls (DOCIST_API_ANONYMOUS=1). They are counted against the caller's IP at the guest limit. A key you do send must be valid: a wrong one is refused, never treated as keyless.

{% else %}

The operator can allow keyless calls with DOCIST_API_ANONYMOUS=1, counted against the caller's IP at the guest limit. This server doesn't, so a POST without a key is refused.

{% endif %}

Errors

Every error is JSON, with one of these statuses:

  • 400 {"error": "…"}: something to fix in the request, such as a missing file or field, a bad option, an upload that isn't what its extension says, or a wrong password. The message says which.
  • 401 {% if not api_anonymous %}{"error": "API key required. Create one at /account."} for a POST without a key, or {% endif %}{"error": "Invalid or revoked API key."} for a wrong or revoked key, or one whose account is disabled.
  • 413 {"error": "…", "code": "upload_too_large", "limit_mb": N}: the request body is over the upload limit that applied to it, given in limit_mb.
  • 429 with a Retry-After header in seconds: {"error": "…"} from the per-IP rate limit, or {"error": "…", "code": "daily_limit", "limit": N, "used": N, "signup_url": "/signup"} at the daily limit, where Retry-After runs to midnight UTC.
  • 500 {"error": "{{ server_error_message }}", "code": "server_error"}: something went wrong on the server. The message is always this one.

Limits & behaviour

  • Rate limit: POSTs are capped per client IP — DOCIST_RATE_LIMIT requests (default 30) per DOCIST_RATE_WINDOW seconds (default 60). Over the cap you get a 429. GETs are never limited. This short-window cap is separate from the daily limit below.
  • Daily limit: each successful call costs one operation from the key owner's daily allowance, shared with their browser use: DOCIST_LIMIT_FREE (default 50) for a free account, unlimited on a paid plan.{% if api_anonymous %} A keyless call costs one from the caller's IP's guest allowance, DOCIST_LIMIT_ANON ({% if guest_limit %}{{ guest_limit }} on this server{% else %}unlimited on this server{% endif %}).{% endif %} Failed calls cost nothing. The day is the UTC date. Every counted response carries X-Docist-Usage-Limit (a number, or unlimited) and X-Docist-Usage-Remaining. Past the limit you get a 429.
  • Upload size: a request whose total body is larger than your account's upload limit (DOCIST_MAX_UPLOAD_MB, default 50 MB) is refused with a 413.
  • Nothing is stored: API uploads and results live in a temporary directory for the length of the request only — unlike the web UI, no file is left in the server's output folder.
  • Content checks: uploads are sniffed against their extension, so a renamed file (a ZIP called .pdf) is refused with a 400.
  • Health: GET /healthz needs no auth and returns {"status": "ok", "job_limits": true, "commit": "…"}. job_limits is false when the start-up check found that the per-job memory cap doesn't hold on this platform. commit is the first 12 characters of the deployed commit (DOCIST_COMMIT, else Railway's RAILWAY_GIT_COMMIT_SHA), or null when neither is set.
